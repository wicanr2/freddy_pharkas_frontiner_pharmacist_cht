## 1. 目標觀眾與核心訊息

三種人會點開這支片，順序就是他們的重要性：

| 觀眾 | 他在意的事 | 片中對應的段落 |
|---|---|---|
| 當年看過《軟體世界》廣告的老玩家 | 「就是這一款，我記得這張圖」 | 開場的廣告原件、對照式蒙太奇 |
| 玩過原文版、想重玩的人 | 中文品質到哪、會不會半吊子 | 對白框特寫、F8 對照、覆蓋率數字 |
| 沒聽過這款、逛到 repo 的人 | 這是什麼遊戲、值不值得裝 | 故事三句話、配藥畫面、下載資訊 |

核心訊息一句話：**1993 年那張廣告上的遊戲，現在整套是中文的。**

要避免的講法：不喊「完美」「極致」「史上最強中文化」；數字自己會說話（5,166／5,181、2,889 字、三平台）。

## 2. 片長與規格

| 項目 | 規格 | 理由 |
|---|---|---|
| 片長 | **70 秒**（±5 秒） | 比 CLAUDE.md ⑦ 的 40–60 秒略長，因為多了「廣告 → 實機」的對照段；超過 90 秒觀眾會流失 |
| 解析度 | 1280×720，25 fps，H.264 yuv420p | 遊戲畫面 640×400 放大 1.5 倍剛好，不會糊 |
| 每畫面停留 | 5–7 秒（對照式）／3–4 秒（單張） | 中文字幕要讀得完；對照式要左右各看一眼 |
| 轉場 | 0.5 秒 fade，不用 zoompan | kb `game-promo-video-ffmpeg` 雷 #1：zoompan 幀數會爆炸 |
| 音訊 | AAC 192k，`aloop` 循環後 `atrim` 到片長 | 同 kb：`-shortest` 會砍掉結尾卡 |

## 3. 敘事結構

三幕，時間分配 2 : 5 : 3。

1. **回憶（0:00–0:19）** — 先放當年的廣告，讓老玩家「認出來」。結尾落在一句沉的：那個年代它沒有中文版。
2. **現況（0:19–1:04）** — 標題卡之後全部是實機畫面。先用廣告那幾格做對照，再展開對白、選單、配藥、F8。
3. **收尾（1:04–1:12）** — 數字、平台、repo 位址、致敬。

節奏設計上，第一幕刻意慢（靜態、字少），第二幕轉快（畫面切換密），第三幕停住讓人記住網址。

## 5. 當年的廣告怎麼入鏡

廣告是這支片的骨架，不是裝飾。用法有三層：

1. **開場三鏡**（#1–#3）建立年代感。廣告原件整張出現一次，之後只裁局部——裁切既是視覺節奏，也讓引用範圍小而明確。
2. **對照蒙太奇**（#6–#8）是全片最重要的段落。廣告當年就用了四張遊戲截圖去賣這款遊戲；現在把其中三格挑出來，右邊放同一個場景的繁中實機畫面。老玩家看的是「這格我記得」，新玩家看的是「這遊戲長這樣，而且是中文」。
3. **不重繪、不修圖**。廣告只做裁切與縮放，不加濾鏡、不去背、不改字。要標示的一律用畫面外的小標，不動原件。

引用範圍與界線：全片出現的廣告文字合計約 60 字，都是可辨識出處的短句，畫面上與片尾都標《軟體世界》。不轉載評測全文，不使用第 114–115 頁的評測掃描頁（那是整頁文章，超出短引用的合理範圍）。

## 7. 音樂與版權 — 要拍板的地方

`rulebook/93` 的鐵則是：推廣片配樂必須用原版真實素材，不可自產（自寫合成器、AI 生成曲、TTS 都不行，音色一聽就假）。同一份規則的但書是：原版音樂是他人著作，**放進會公開的影片等於散布**，動手前要先讓人決定。

這支片預設會公開（README、Release 頁、可能上傳影音平台），所以兩件事要一起看：

**技術上音樂從哪來**

這是 CD talkie 版，`resource.aud` 有 600MB 的真人配音與演唱，開場〈The Ballad of the Frontier Pharmacist〉是實際錄音，不是 MIDI。所以有兩條路：

- **A. 即時側錄 MT-32**（SQ3 已驗證的做法）：`SDL_AUDIODRIVER=disk` ＋ `--music-driver=mt32 --extrapath=/home/anr2/cht/mt32`，不設 `SDL_DISKAUDIODELAY=0`（設了排序器不會走，錄出來是靜音）。錄到的是 Munt 模擬的真實 MT-32 輸出，音色正宗。
- **B. 直接取 CD 的演唱錄音**：音樂性最好，情感最對，但那是一份完整的錄音著作，公開風險最高。

**版權上怎麼處理**

| 方案 | 配樂 | 公開風險 | 適用 |
|---|---|---|---|
| **甲（建議）** | 原版 MT-32 側錄（路線 A） | 中。是遊戲配樂的模擬合成輸出，仍屬原作曲著作 | 先做這版，本機保存；要不要公開由 Hermes 決定 |
| 乙 | CD 演唱錄音（路線 B） | 高。錄音著作＋音樂著作 | 只建議本機留存，不公開 |
| 丙 | 授權／CC 的西部風配樂 | 低 | 若確定要上影音平台，改用這條 |
| 丁 | 不放配樂，只用遊戲音效 | 最低 | 片子會單薄，不建議 |

另外要一併提醒的是：**片中的遊戲畫面本身也是 Sierra／Activision 的著作**。粉絲中文化專案放實機畫面是慣例，但這不等於獲得授權；如果要上傳到會自動比對版權的平台，這一點跟配樂一樣要先想清楚。

**待決事項一**：配樂走甲、丙還是丁。沒有結論之前不進第 8 節的合成階段。

## 8. 製作流程

三段式，每段一支腳本、輸入輸出都是檔案，可重跑。

### 第一段：擷取（`tools/cap_promo.sh`，待寫）

沿用 `freddy-capture:latest` 這顆 image（已有 Xvfb／xdotool／ImageMagick／ScummVM runtime）：

```bash
docker run --rm --name freddy-video-capture -v "$PWD":/w -w /w freddy-capture:latest ...
```

- 場景用除錯器換，不玩劇情。
- 每張存 1280×800 全螢幕，後製再裁。
- 音訊在同一顆 image 錄（有 SDL runtime），轉檔在 `game-video:latest` 做（有 ffmpeg）。
- **[HARD]** `docker run` 一律 `timeout` 包住；收工只 `docker rm -f freddy-video-*`，不碰別人的容器與 image。

### 第二段：素材（`tools/mk_promo_assets.sh`，待寫）

在 `game-video:latest` 裡用 ImageMagick 生成：

```bash
# 遊戲畫面裁切（已實測，三個不同場景的截圖都對得上）
convert in.png -crop 640x400+480+304 +repage -resize 960x600 out.png

# 對照式併排：左廣告右實機，各自加細框，上角貼小標
convert ad_crop.png shot.png +append ...
```

字型先 `ls` 確認存在再用（kb 雷 #5：`fonts-noto-cjk` 只有 Regular／Bold，沒有 Medium）。中文字幕用襯線體。

### 第三段：合成（`tools/mk_promo.sh`，待寫）

照 kb 的 CPU-safe 骨架：靜態圖＋fade，不用 zoompan；`--cpus=2`、`-preset veryfast -threads 2`；最後鋪配樂用 `aloop` 再 `atrim`，不加 `-shortest`。

產物放 `out/video/`，素材放 `out/video_src/`。兩者都含遊戲畫面與（可能的）原版音樂，**一律 gitignore，不入版控**。

## 11. 驗收標準

做完之後逐條對，任何一條沒過就不算完成：

**素材真實性**
- 每一格遊戲畫面都是引擎實機擷取，沒有設計稿、沒有 mockup、沒有重繪。
- 中文畫面用的是 v1.0 的 `translation.tsv` 與字型（md5 對得上 `dist-cht/`）。
- 配樂來自原版（側錄或授權曲），不是自產合成。

**技術**
- `ffprobe` 確認視訊與音訊長度相同（差 < 0.1 秒），結尾卡沒有被砍。
- `volumedetect` 的 `mean_volume` 不是 -91 dB（靜音）、`max_volume` < 0（沒有削波）。
- 合成全程 docker，`--cpus=2`，沒有 zoompan 幀數爆炸。
- 收工後 `docker ps -a | grep freddy-video` 為空，且沒有動到任何非本專案的容器或 image。

**內容**
- 廣告引用不超過短句範圍，畫面上與片尾都標《軟體世界》。
- 片中所有中文沒有錯字（片尾卡的數字逐一對過 README）。
- 沒有劇透：不出現結局畫面、不出現幕後主使、不出現關鍵解法。
- repo 網址正確且可點。

**產出物**
- `out/video/`、`out/video_src/` 都在 `.gitignore` 裡，`git status` 乾淨。
